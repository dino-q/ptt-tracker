# moptt 熱門演算法實證研究與我們的複製實作

> 2026-08-23。研究方法：攔截 moptt.tw/popular 的 API（moptt.azurewebsites.net/api/v2/hotpost，
> Authorization 金鑰取自其網頁前端）、抓 120 筆 feed＋單板 feed，並抽 10 篇回 PTT 對地面真相。
> 本檔是 `server.py run_hot`（v4）的設計依據。

## 實證發現

1. **`hits` 是 moptt 自家 App 的瀏覽量，不是任何 PTT 公開數據**。
   對照證據：hits=768 的表特文在 PTT 只有 10 則留言；hits=11 的媽佛文有 393 則留言。
   → 這是它的核心排序信號，**外部無法取得**（Dino 已拍板：不依賴其 API，用機制複製＋信號替代）。
2. **收錄制**：文章信號越過門檻 → 記 `acceptedDate`，之後固定在 feed；多數文發文後
   中位數 1.5 小時被收錄。
3. **Feed 排序＝acceptedDate 新→舊**，120 筆實測嚴格全序遞減；不是分數榜。
4. **舊文回鍋**：2015 年、2025 年的舊文只要「現在」信號過門檻就被今日收錄——只看信號當下值。
5. **板級門檻**：與板活躍度成正比（八卦收錄線 ≈376 hits、媽佛 ≈11）。
6. **沒有每板頁面限額**：八卦一頁可佔 11-15/20 篇。
7. **看板自選是產品本體**：API 以 `b=板&b=板…` 傳使用者選的看板集合（預設六板），
   「熱門」＝自選集合的聯集。

## 我們的複製（run_hot v4）

| moptt 機制 | 我們的實作 |
|---|---|
| 信號：App 瀏覽量 hits | **總留言數**（推+噓+→，公開資料中與「多少人在看」最相關的代理） |
| 板級門檻 | 依板人氣：≥5000 人→150 留言、≥1500→100、≥400→50、其餘→25 |
| 收錄 accepted_at | 過門檻當下記錄；本機存 track 快取、線上由 build_site 從上一版已部署 JSON 繼承 |
| feed 排序 | accepted_at 新→舊（UI 預設排序「最新熱門」；另提供正在起飛/總留言數） |
| 舊文回鍋 | 探索走 `recommend:` 搜尋（搜全板歷史不限最新頁），舊文再熱自然回鍋 |
| 收錄後凍結 | 已收錄文不重抓統計、feed 位置固定（也大幅省請求） |
| 保留期 | accepted_at 起 10 天（moptt 未觀測到明確上限，10 天是我們的資源取捨），總量上限 200 |
| 看板自選 | UI 看板膠囊顯示/隱藏（收折式）＋本機 task `boards` 自訂掃描清單 |

## 已知與 moptt 的必然差異（誠實聲明）

- 內容不會 100% 相同：信號不同（他們看 App 點閱、我們看留言量），例如「多人看但少人留言」
  的表特/圖文會被我們低估。這是不依賴其私有數據的必然代價（Dino 已知情拍板）。
- 收錄延遲：我們白天每小時跑一輪，收錄粒度 1 小時；moptt 中位數 1.5 小時內，量級相當。

## 探索參數換算

`recommend:{門檻÷3，夾在 10–50}`：總留言≈3×淨推的粗略經驗比，寧可多撈進驗證階段
（驗證才是收錄判準，探索只是省請求的預過濾）。
